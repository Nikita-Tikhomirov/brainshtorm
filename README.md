# Runet Niche Analyzer

MVP инструмента для первичного отбора ниш под Рунет. Он принимает пачку до 100 seed-направлений, оценивает спрос, тренд, конкуренцию, бюджет, сложность и выдает CSV/Markdown-отчет с вердиктами, строгими доказательствами и готовыми launch-рекомендациями.

Есть два режима:

- `Yandex Wordstat API` — пользователь вставляет API key и folder ID прямо в интерфейсе, ключ и параметры сохраняются локально на компьютере.
- `Demo` — не ходит во внешние API, а генерирует детерминированные метрики по тексту направления.

SERP-анализ подключен как второй этап: сначала пачка ранжируется по Wordstat/Demo-метрикам, затем выдача проверяется только для финалистов. Дополнительно можно включить проверку коммерческих кластеров: приложение берет горячие фразы из Wordstat, группирует их по намерению и проверяет SERP по нескольким representative-запросам. Для каждого SERP приложение автоматически считает `offer_gap`: типы конкурентов, признаки офферов в title/snippet и слабые места выдачи.

AI-вердикт подключен как третий этап: GPT или DeepSeek анализирует финалистов по метрикам и SERP, затем добавляет практический вывод в отчет.

Даже без GPT/DeepSeek приложение формирует `Launch recommendation`: что запускать, для кого, какие посадочные страницы делать, почему проект может продвинуться, какой первый тест запустить и какие факторы подтверждают идею. В режиме `auto` тип проекта выбирается отдельно для каждой ниши: SEO-сайт, лидогенерация, сервис, Telegram-продукт, инфопродукт или каталог. Выбор делается через локальный scoring кандидатов: каждый тип получает баллы по текстовым сигналам, спросу, коммерческому интенту, конкуренции, бюджету, сложности и риску. Рекомендация учитывает выбранный тип проекта и найденные слабые места офферов конкурентов: цену, гарантию, скорость, доставку, отзывы, наличие, сервис и понятный следующий шаг.

Отчет работает в строгом evidence-режиме: `score`, SERP-поправки, `offer_gap` и `opportunity_score` раскрываются через факторы, вклад в балл, исходное значение и источник данных. Это не гарантия прибыли, а проверяемый фильтр гипотез.

## Установка

```powershell
python -m pip install -e .
```

## Запуск

Самый удобный вариант — ярлык на рабочем столе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\create_desktop_shortcut.ps1
```

После этого запускайте `Runet Niche Analyzer` двойным кликом с рабочего стола. Ярлык поднимает Streamlit на `http://localhost:8501` и открывает браузер. Если приложение уже запущено, второй сервер не стартует, просто откроется браузер.

Ручной запуск:

```powershell
.\run_app.cmd
```

Прямой запуск Streamlit:

```powershell
python -m streamlit run src/brainshtorm/app.py
```

CLI-режим:

```powershell
python -m brainshtorm.cli examples/directions.csv --output-dir out/demo --provider demo
```

Результаты:

- `out/demo/analysis.csv` — таблица с оценками.
- `out/demo/report.md` — отчет с ранжированием, launch-рекомендациями, шагами продвижения и рисками.

## Формат CSV

Обязательные колонки:

- `direction` — seed-направление.
- `region` — регион анализа.
- `budget_rub` — бюджет запуска в рублях.
- `max_difficulty` — максимальная допустимая сложность от 1 до 10.
- `project_type` — тип проекта. Можно указать `auto`, тогда приложение выберет тип проекта по тексту направления и метрикам.

Поддерживаемые типы проекта:

- `auto`
- `seo_site`
- `leadgen`
- `service`
- `telegram`
- `infoproduct`
- `marketplace`

Пример:

```csv
direction,region,budget_rub,max_difficulty,project_type
ремонт роботов пылесосов,Москва,150000,6,auto
курсы нейросетей,Россия,100000,7,auto
```

## Работа через интерфейс

1. Запустите Streamlit.
2. В боковой панели выберите режим `Yandex Wordstat API` или `Demo`.
3. Для реального режима вставьте `Yandex API key` и `Yandex folder ID`.
4. Вставьте список направлений по одному на строку.
5. Выберите регион, бюджет, сложность и тип проекта. По умолчанию стоит `Авто (сам выберет)`.
6. Включите `Проверять выдачу финалистов`, если нужен SERP-анализ.
7. Выберите, сколько финалистов и результатов выдачи проверять.
8. Включите `Проверять коммерческие кластеры`, если нужно искать слабые места не только по seed-запросу.
9. Выберите, сколько кластеров на нишу проверять. Практичный старт — 3-4 кластера.
10. Включите `Генерировать AI-вердикт финалистов`, если нужен AI-вывод.
11. Выберите `GPT` или `DeepSeek`, вставьте API key и при необходимости измените модель.
12. Нажмите `Сохранить параметры`, если хотите просто запомнить настройки без анализа.
13. Нажмите `Запустить анализ`.
14. Скачайте `analysis.csv` или `report.md`.

Для API-ключа нужен сервисный аккаунт Yandex Cloud с ролью `search-api.webSearch.user` и ключом со scope `yc.search-api.execute`.

Настройки хранятся в профиле пользователя:

```text
%USERPROFILE%\.brainshtorm\settings.json
```

На Windows Yandex/OpenAI/DeepSeek API key и folder ID записываются через DPAPI-защиту текущего пользователя. Файл настроек находится вне репозитория и не попадает в git. Логи фонового запуска пишутся в `out\logs`.

## Следующий этап

Реальный провайдер Yandex Search API Wordstat уже подключен:

- `GetTop` для спроса и похожих запросов;
- `GetDynamics` для тренда;
- `GetRegionsDistribution` для региональности.

SERP-проверка использует `WebSearch.Search` (`/v2/web/search`) и XML-ответ из `rawData`. Она добавляет в таблицу:

- `serp_difficulty` — оценка сложности выдачи;
- `serp_delta` — поправка к итоговому score;
- `offer_gap` — автоматическая оценка зазора в офферах конкурентов по title/snippet/domain;
- `serp_weak_spots` — короткая сводка слабых мест выдачи;
- `top_domains` — первые домены из выдачи.
- `keyword_clusters` — коммерческие кластеры и оценка сложности SERP по ним.
- `opportunity_score`, `launch`, `first_test` — готовая рекомендация, что запускать и как проверить старт.
- `project_type` — тип проекта, который задан вручную или выбран автоматически для конкретной ниши.
- `score_confidence`, `evidence_count` — насколько расчет подтвержден дополнительными проверками и сколько доказательств собрано.

Markdown-отчет дополнительно содержит:

- `Strict evidence` — список фактов: Wordstat, SERP, кластеры, домены, offer gap.
- `Project type inference` — доказательство авто-выбора типа проекта, если в CSV или интерфейсе выбран `auto`.
- `Score formula` — вклад каждого фактора в итоговый `score`.
- `Opportunity formula` — вклад каждого фактора в `opportunity_score`.

Кластерный SERP делает дополнительные поисковые запросы: примерно `финалисты x кластеры` сверх базовой проверки seed-запросов. Например, 10 финалистов и 4 кластера — это до 40 дополнительных SERP-проверок.

AI-слой уже добавлен через GPT/OpenAI Responses API и DeepSeek Chat Completions API. Ключ вставляется в интерфейсе и сохраняется локально в защищенном файле настроек. AI получает не только базовые метрики, но и SERP, кластеры, `offer_gap`, слабые места выдачи, формулы, evidence-ledger и локальную launch-рекомендацию. Prompt запрещает придумывать факты вне собранных данных.

Отдельная опция `Уточнять авто-тип проекта через AI` делает батчевый GPT/DeepSeek-проход до расчета score: AI видит метрики и локальные candidate scores, но может выбрать только один из разрешенных типов проекта. Если AI вернул некорректный JSON, неизвестный тип или API недоступен, приложение продолжает работу на локальном выборе.

Для DeepSeek клиент сначала использует thinking mode. Если API вернул пустой финальный `content`, приложение автоматически делает один повтор без thinking mode и с увеличенным лимитом токенов. Если повтор тоже пустой, ошибка показывает `finish_reason`, наличие `reasoning_content` и факт fallback-повтора.

Следующий практический шаг — добавить кэширование SERP/AI-ответов, чтобы повторные прогоны одной пачки не тратили API-запросы заново.

API-ключи не сохраняются в репозитории.
