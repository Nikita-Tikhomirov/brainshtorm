# ТЗ: Runet Niche Analyzer

Дата: 2026-06-01

## Цель

Сделать первый рабочий MVP инструмента для поиска ниш под Рунет. Пользователь загружает пачку до 100 направлений, задает бюджет и допустимую сложность, а система собирает или принимает рыночные метрики, оценивает ниши и выдает шорт-лист продуктов для запуска и продвижения.

## Контекст и ограничения

- Основной рынок: Рунет и Яндекс.
- Основной источник спроса: Yandex Search API Wordstat.
- Key Collector не является ядром MVP, потому что публичного внешнего API управления программой нет. Его можно подключить позже через CSV/XLSX импорт и экспорт.
- Первый MVP должен работать без внешних ключей в демо-режиме, чтобы можно было проверять логику, тесты и формат отчетов.
- Реальный сбор через API должен быть вынесен за интерфейс провайдера данных, чтобы заменить демо-данные на Yandex API без переписывания скоринга.
- Лимит пачки: до 100 seed-направлений за один прогон.
- Секреты не хранятся в коде. API-ключи передаются через переменные окружения.

## Пользовательский сценарий

1. Пользователь готовит CSV со списком направлений.
2. В каждой строке есть seed-фраза, регион, бюджет, желаемая сложность и тип проекта.
3. Пользователь запускает анализ.
4. Инструмент получает или симулирует рыночные метрики.
5. Инструмент считает score, сортирует направления и присваивает вердикт:
   - `take` — стоит брать в работу;
   - `review` — перспективно, но нужна ручная проверка;
   - `skip` — не брать сейчас.
6. На выходе создаются CSV и Markdown-отчет.

## Формат входного CSV

Обязательные колонки:

- `direction` — seed-направление или фраза.
- `region` — регион анализа, например `Россия`, `Москва`, `Санкт-Петербург`.
- `budget_rub` — бюджет запуска в рублях.
- `max_difficulty` — максимальная допустимая сложность от 1 до 10.
- `project_type` — тип проекта: `seo_site`, `leadgen`, `service`, `telegram`, `infoproduct`, `marketplace`.

Пример:

```csv
direction,region,budget_rub,max_difficulty,project_type
ремонт роботов пылесосов,Москва,150000,6,leadgen
курсы нейросетей,Россия,100000,7,infoproduct
запчасти для квадроциклов,Россия,250000,6,seo_site
```

## Источники данных

### MVP

- `demo` provider: детерминированные локальные данные для разработки, тестов и демонстрации.
- `csv` provider: возможность позже подавать заранее собранные метрики.

### Реальный сбор после MVP

- Wordstat `GetTop`: похожие запросы, частотность, ассоциации.
- Wordstat `GetDynamics`: динамика и тренд спроса.
- Wordstat `GetRegionsDistribution`: региональное распределение.
- Yandex Search API SERP: проверка выдачи только для финалистов, чтобы не сжигать бюджет.
- Key Collector: опциональный ручной источник семантики через CSV/XLSX.

## Экономика API

На дату 2026-06-01 актуальная оценка для Wordstat:

- `GetTop`: 20 ₽ за 1000 запросов.
- `GetDynamics`: 20 ₽ за 1000 запросов.
- `GetRegionsDistribution`: 50 ₽ за 1000 запросов.

Пачка 100 направлений с тремя Wordstat-запросами на направление стоит около 9 ₽. Основные расходы будут не на Wordstat, а на SERP, внешние базы конкурентов и рекламные тесты.

## Скоринг

Score считается по шкале 0-100.

Факторы:

- спрос по seed и расширенным запросам;
- тренд спроса;
- региональная концентрация;
- коммерческий интент;
- сила конкурентов;
- соответствие бюджету запуска;
- соответствие допустимой сложности;
- риск YMYL или правовых ограничений;
- сезонность.

Первичная формула MVP:

```text
score =
  demand_score * 0.25 +
  trend_score * 0.15 +
  commercial_score * 0.15 +
  competition_score * 0.15 +
  budget_fit_score * 0.15 +
  difficulty_fit_score * 0.10 +
  regional_score * 0.05
  - risk_penalty
```

Вердикт:

- `take`: score >= 75;
- `review`: 50 <= score < 75;
- `skip`: score < 50.

## Выходные данные

Для каждого направления:

- итоговый score;
- вердикт;
- краткое объяснение;
- спрос;
- тренд;
- конкуренция;
- соответствие бюджету;
- рекомендуемый продукт;
- первые шаги продвижения;
- риски.

Форматы:

- `analysis.csv` — таблица для сортировки и фильтрации.
- `report.md` — человекочитаемый отчет с топом ниш и рекомендациями.

## Архитектура

Компоненты:

- `models` — dataclass-модели входа, рыночных метрик и результата.
- `io` — чтение CSV, валидация пачки и запись результатов.
- `providers` — интерфейс источника данных и демо-провайдер.
- `scoring` — расчет score, вердикта и рекомендаций.
- `reporting` — Markdown-отчет.
- `cli` — запуск анализа из командной строки.

## Ошибки и ограничения

- Если в CSV больше 100 строк, инструмент завершает работу с понятной ошибкой.
- Если обязательная колонка отсутствует, инструмент показывает список недостающих колонок.
- Если бюджет или сложность некорректны, строка считается ошибочной.
- Если API-ключ отсутствует, реальный провайдер не запускается, но демо-режим работает.
- Автоматический вердикт не является финальным инвестиционным решением. Финалисты требуют ручной проверки и теста спроса.

## Definition of Done для MVP

- Есть сохраненное ТЗ и план.
- Есть Python-пакет с CLI.
- Есть демо-провайдер, работающий без внешних ключей.
- CSV до 100 направлений валидируется.
- Score и verdict считаются детерминированно.
- Генерируются CSV и Markdown-отчет.
- Есть тесты для валидации, скоринга и отчетности.
- README объясняет запуск.
- Проверки пройдены.
- Изменения закоммичены и запушены.
